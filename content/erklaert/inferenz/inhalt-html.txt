<div class="erklaert">
<div class="tldr">
<p><strong>Inferenz</strong> heißt: ein fertig trainiertes Modell benutzen. Die <a href="/erklaert/parameter/">Parameter</a> stehen fest, es wird nur noch gerechnet – Eingabe rein, Ausgabe raus. Das passiert bei jeder einzelnen Chat-Nachricht.</p>
<p>Bei Sprachmodellen läuft das in zwei Phasen: Erst wird die ganze Eingabe auf einmal verarbeitet (<strong>Prefill</strong>), dann entsteht die Antwort Token für Token (<strong>Decode</strong>). Für jedes einzelne Token müssen dabei praktisch alle Parameter aus dem Speicher gelesen werden – deshalb bestimmt die <strong>Speicherbandbreite</strong> der Hardware, wie schnell ein Modell schreibt.</p>
</div>

<h2 id="training-vs">Training und Inferenz</h2>
<div class="tbl-wrap">
<table>
  <thead><tr><th></th><th>Training</th><th>Inferenz</th></tr></thead>
  <tbody>
    <tr><td><strong>Was passiert</strong></td><td>Parameter werden angepasst</td><td>Parameter werden nur gelesen</td></tr>
    <tr><td><strong>Wie oft</strong></td><td>einmal pro Modellversion</td><td>bei jeder Anfrage, millionenfach am Tag</td></tr>
    <tr><td><strong>Dauer</strong></td><td>Wochen bis Monate</td><td>Sekunden bis Minuten</td></tr>
    <tr><td><strong>Hardware</strong></td><td>riesige Rechner-Verbünde</td><td>von großen Rechenzentren bis zum eigenen Laptop</td></tr>
  </tbody>
</table>
</div>
<p>Einzeln ist eine Inferenz billig. Weil sie aber ständig passiert, verbrauchen Anbieter insgesamt viel Rechenleistung dafür – inzwischen oft mehr als für das Training.</p>

    <p>Jetzt entsteht die Antwort, streng nacheinander: Jedes Token hängt vom vorigen ab. Pro Token ein kompletter Durchgang durchs Modell. Das bestimmt, wie schnell der Text erscheint.</p></div>
</div>

</figure>

<p>Damit beim Schreiben nicht jedes Mal die ganze Eingabe neu berechnet werden muss, merkt sich das Modell die Zwischenergebnisse jedes bisherigen Tokens im <strong>KV-Cache</strong> (siehe <a href="/erklaert/kontextfenster/">Kontextfenster</a>). Pro neuem Token kommt nur noch ein Eintrag dazu.</p>

<h2 id="bandbreite">Warum Speicherbandbreite entscheidet</h2>
<p>Beim Schreiben steckt die meiste Zeit nicht im Rechnen, sondern im <strong>Lesen</strong>: Für jedes einzelne Token müssen die Gewichte aus dem Grafikspeicher zu den Recheneinheiten wandern. Bei einem Modell mit 140 GB Gewichten sind das 140 GB – pro Token. Daraus folgt eine einfache Obergrenze:</p>
<pre><code>Tokens pro Sekunde  ≲  Speicherbandbreite / Größe der Gewichte</code></pre>

<h2 id="batching">Viele Nutzer auf einmal</h2>
<p>Wenn das Lesen der Gewichte der Engpass ist, liegt ein Trick nahe: Einmal gelesene Gewichte gleich für viele Anfragen verwenden. Genau das machen Anbieter mit <strong>Batching</strong> – die Grafikkarte erzeugt das nächste Token für Dutzende Gespräche gleichzeitig. Für den Einzelnen wird es kaum langsamer, die Kosten pro Token sinken aber drastisch.</p>
<div class="cards">
  <div class="card"><div class="num">⇄</div><h4>Eingabe ist billiger</h4><p>Eingabe-Tokens werden im Prefill parallel verarbeitet, Ausgabe-Tokens einzeln nacheinander. Deshalb kosten Ausgabe-Tokens bei APIs meist ein Mehrfaches.</p></div>
  <div class="card"><div class="num">♻</div><h4>Caching</h4><p>Bleibt der Anfang einer Anfrage gleich – etwa ein langer Systemprompt –, können Anbieter das Prefill zwischenspeichern. Solche Tokens werden dann deutlich günstiger berechnet.</p></div>
  <div class="card"><div class="num">⚡</div><h4>Spekulatives Dekodieren</h4><p>Ein kleines Modell rät mehrere Tokens voraus, das große prüft sie in einem Durchgang. Stimmen sie, spart man Zeit – am Ergebnis ändert sich nichts.</p></div>
</div>

<h2 id="irrtuemer">Häufige Irrtümer</h2>
<div class="myth">
  <div><b>„Das Modell tippt absichtlich langsam, damit es menschlich wirkt.“</b> – Nein, es entsteht tatsächlich Token für Token. Die Anzeige zeigt nur, was schon fertig ist.</div>
  <div><b>„Ein schnelleres Modell ist ein schlechteres.“</b> – Nicht unbedingt. Tempo hängt von Hardware, Auslastung, Optimierung und Bauweise ab, nicht nur von der Größe.</div>
  <div><b>„Beim Benutzen lernt das Modell.“</b> – Bei der Inferenz werden die Parameter nur gelesen, nie verändert.</div>
  <div><b>„Für ein großes Modell braucht man vor allem schnelle Prozessoren.“</b> – Vor allem braucht man viel und schnellen Speicher. Deshalb sind Grafikkarten mit großem, sehr schnellem Speicher so begehrt.</div>
